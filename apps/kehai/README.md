# 気配 -Kehai-

勉強中・作業中・就寝前など、時間を決めるだけで「隣に誰かがいる気配」を感じられる汎用の伴侶アプリ。呼吸の音を土台に、時々応援や気遣いの声をかけたり、伸び・ため息・鼻歌などの生活音がランダムに挟まる。Expo (React Native) 製。

凪・隣と同じ「凡庸なサブスクではなく、買い切りの廉価版」路線。TTSで台詞を動的生成するため、声優ライセンス費用ゼロで買い切り¥480の複数キャラクターを提供する。

## キャラクター設計について

「ギャル/清楚/若い子/熟女/動物/男友達/年齢別」という要望は、**口調のスタイル**として表現した。内容は全て応援・気遣いで統一しており、恋愛的・扇情的な表現は含めていない。ビジュアルはリアルなイラストではなく、抽象的なアイコンマーク(暖色の光を柔らかい弧が包み込むデザイン)で表現している。イラストレーターへの発注やAI画像生成サービスとの連携は本セッションの対応範囲外(商用利用可能な無料ツールの候補は会話ログ参照)。

### 9キャラクター(3カテゴリ)

| カテゴリ | キャラクター |
|---|---|
| 女友達 | 清楚系(無料)・ギャル系・後輩系(年下)・お姉さん系(年上) |
| 男友達 | 爽やか系(同世代)・兄貴系(頼れる先輩)・渋め系(落ち着いた大人) |

清楚系のみ無料、他8キャラは買い切り¥480(バンドル、キャラ単位課金ではない)で一括解放。

### ランダム性について

- **声かけの間隔**: 1分30秒〜4分でランダムに次の間隔を決め直す(固定スケジュールにしない)
- **内容の抽選**: シチュエーションを選んでいる場合、応援/気遣い/シチュエーションの一言を重み付き抽選(48/32/20%)。同じトリガーで直前に使った文言は選ばれない
- **生活音**: 45秒〜110秒でランダムに次のタイミングを決め、ため息・伸び・鼻歌・ページめくりからランダムに1つ再生

これらの組み合わせにより「毎回同じにならない」体験を、固定の台本を用意せずに実現している。

### 音楽を止めない

凪・隣と同じく `expo-audio` の `duckOthers` で、音楽アプリを止めずに声・環境音を重ねる。

### プレミアムプラン(月額・お試し版)

キャラ解放(¥480買い切り)とは別枠で、月額プラン(¥480/月、`app/purchases.ts` の `usePremiumPurchase`)が2つの機能を解放する。

- **AIと話すモード**: セッション実行中に「AIと話す」ボタンから、キャラの声を聴きながらAIと会話できる。テキスト入力・送信・履歴表示は動作し、Web版はブラウザ標準のWeb Speech APIでマイク入力(音声→テキスト)にも対応している。ただし実際のAI応答生成にはユーザー自身のAPIキーを保持するバックエンドサーバー(プロキシ)が別途必要で、このリポジトリの開発環境だけでは用意・疎通確認ができないため、現状は `app/aiChat.ts` の `getAIResponse()` が固定フレーズを順番に返す**お試し版**になっている。本番化の手順・差し込みポイントは同ファイル冒頭のコメントに詳細を記載。iOS/Androidネイティブでの音声入力も同様の理由(config-pluginパッケージ+実機ビルドが必要)で未配線(`app/useSpeechInput.ts` 参照)
- **名前で呼んでもらう機能**: ホーム画面でニックネームを入力しておくと(設定自体は無料)、応援(cheer)トリガーが来た時に40%の確率で、通常のセリフの代わりに「ねぇねぇ{name}、もうちょっとだよ!」のようなニックネーム入りのセリフを話す(`app/nameLines.ts` にキャラごとの台詞、`app/useVoiceCompanion.ts` に抽選ロジック)。追加コストがかからない機能だが、AIと話すモードと抱き合わせることで月額プランの提供価値を底上げしている

月額という位置づけだが、実際の定期購読課金にはストア側でのサブスクリプション商品登録とサーバー側でのレシート検証(App Store Server Notifications / Play RTDN)が別途必要で、現状は凪・隣と同じAsyncStorageスタブで「購入済みか」だけを表現している(詳細は `app/purchases.ts` 冒頭のコメント)。

## 音声について

現在は端末標準のTTS(expo-speech)。呼吸ループ・生活音は `scripts/generate-sounds.js` によるプロシージャル生成(ノイズ整形音、著作権フリー)。品質を上げる場合は隣の音声と同様、高品質TTS APIや実録音への差し替えを検討。

## MVPスコープ

- 実装済み: 9キャラクター(女友達4/男友達3/どうぶつ2)× 声の高さ3段階、シチュエーション選択(6種+なし、仕事中モードを強化)、時間選択(お試し5分/30分/1時間/2時間)、ランダム間隔・重み付き内容での声かけ、呼吸ループ+ランダム生活音、音楽ダッキング、買い切り解放の状態管理とペイウォールUI、ブランドアイコン/スプラッシュ、プレミアムプラン(月額。AIと話すモード+名前で呼んでもらう機能。会話UI・Web版マイク入力・TTS読み上げ・名前差し込みは動作、AI応答は固定フレーズのお試し版)
- 未実装(v1では意図的に見送り): セッション履歴の保存、実際のストア決済連携(特に定期購読の受注・更新・解約を扱うサーバー側検証)、ユーザー選択制のキャラクタービジュアル(イラスト/アバター)、AI応答生成用のバックエンドサーバー連携、iOS/Androidネイティブでの音声入力

## 次のアクション

`docs/release-runbook.md` を参照。特に:

1. `app.json` の `ios.bundleIdentifier` / `android.package`(現在は仮の `com.kehai.presence`)を確定
2. キャラクタービジュアルを本格的に作り込みたい場合、Bing Image Creator / SeaArt AI等(商用利用可否は都度規約を確認)で生成した画像に差し替え、またはユーザー自身がお気に入りの画像をアプリ内で設定できる「アバター選択」機能の追加を検討
3. 「AIと話す」モードを本番化する場合、LLM APIキーを保持する軽量バックエンド(プロキシサーバー)を用意し、`app/aiChat.ts` の `getAIResponse()` をそのエンドポイントへの `fetch` に差し替える(詳細は同ファイル冒頭のコメント)。iOS/Androidでの音声入力対応も、その際に `@jamsch/expo-speech-recognition` 等のネイティブモジュール導入とあわせて検討
