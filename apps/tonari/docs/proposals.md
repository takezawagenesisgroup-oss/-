# プラスアルファ機能の提案

今回の実装で追加したもの(ハプティクス通知、週間サマリー/連続記録)以外に、今後盛り込むと良さそうな機能案を効果とコストの見立てつきでまとめた。優先度は「今すぐ着手する価値が高い」順。

## 今回追加で実装したもの(このセッションで対応済み)

当初の依頼(アイコン・ストア文言)に加えて、実装レベルで気づいた改善点も合わせて対応した。

- **音楽ダッキング**: Spotify等を止めずに声を重ねる(iOSは確実、Androidはベストエフォート)
- **台詞の連続repeat回避**: 同じトリガーで直前と同じ文言を選ばない
- **ランニング/ウォーキングのモード切替**: マイルストーンの刻み幅・ペース変化の閾値をモードごとに調整、デモの疑似ペースも連動
- **ラン履歴の保存・一覧**: 日時・モード・口調・距離・時間・平均ペースを記録
- **週間サマリー・連続記録(ストリーク)**: 履歴データから自動計算
- **ハプティクス通知**: 発話と同時に軽い振動(イヤホン未装着時の気づきやすさ向上)
- **ブランドアイコン一式**: 「走路+声の波」マーク

## 優先度A: 次に着手する価値が高いもの

### 1. ニックネーム呼びかけ
初回起動時に呼び名を1つ設定してもらい、台詞の一部に `{name}` を差し込む(例:「〇〇さん、いいペースです」)。既存の `personas.ts` のテンプレート置換の仕組みをそのまま拡張できるため、実装コストは小さいわりに「自分だけの伴走者」感が大きく上がる。
**規模: S** / 依存: なし、単独で実装可能

### 2. 目標ペース設定 + リアルタイム比較
「1kmを6分で」のような目標ペースを設定し、「目標より20秒速い/遅い」を通過報告に組み込む。現状のトリガー(`distance`)に目標ペースとの差分情報を足すだけなので、`useRunSession.ts` の変更のみで実現できる。ガチ勢のランナーに刺さる機能。
**規模: M** / 依存: なし

### 3. インターバルトレーニング(ラン・ウォーク自動切替)音声案内
「3分走って1分歩く」を繰り返すランウォーク法(Galloway method)のような、時間ベースで自動的にモードを切り替えつつ音声で案内する機能。初心者〜復帰ランナーに人気の高いトレーニング形式で、他アプリとの差別化になりやすい。トリガー種別を1つ追加(`intervalSwitch`)し、タイマーベースの新しいセッションモードを作る必要がある。
**規模: M〜L** / 依存: なし

## 優先度B: データが貯まってから効いてくるもの

### 4. 詳細な統計ダッシュボード
現状の週間サマリー(直近7日間の合計距離・回数、連続記録)を拡張し、月間推移グラフ、ペースの向上傾向、モード別・口調別の内訳などを表示する。`dataviz` スキルを使ってグラフ化する想定。
**規模: M** / 依存: 履歴データがある程度溜まった後の方が価値を実感しやすい

### 5. ルートマップ表示
GPS軌跡を地図上に描画し、走り終えた後に「今日のコース」を振り返れるようにする。`react-native-maps` の追加が必要で、位置情報を(距離計算用の一時利用ではなく)座標列として保存するようプライバシーポリシーの見直しも伴う。
**規模: L** / 依存: 地図タイルの利用規約確認、プライバシーポリシーの更新

## 優先度C: 効果は大きいが外部要因に依存するもの

### 6. 共有カード画像の生成(SNSシェア)
走行後に「距離・時間・ペース」を入れたシェア用画像を自動生成し、Instagram StoriesやXに投稿しやすくする。フィットネスアプリの定番のバイラル導線。`react-native-view-shot` 等でスクリーンショット合成する形なら比較的小さい実装で作れる。
**規模: M** / 依存: なし(この環境でも実装・検証可能)

### 7. Apple Health / Google Fit 連携
ワークアウトとして記録をHealthアプリ側にも書き込む。健康管理アプリと併用しているユーザーへの訴求として有効。iOSは `HealthKit` の Capability を Apple Developer Portal 側で有効化する必要があり、人間の作業が伴う。
**規模: M** / 依存: **Apple Developer Portal側の設定(人間の作業)が必要**

### 8. 高品質TTS(ElevenLabs等)の有料オプション
現状の端末標準TTSより自然な音声を、追加のサブスクまたは都度課金で提供する。「無料版は端末TTS、プレミアムは高品質AI音声」という三層目の収益化になり得るが、API利用料が発生し続ける(原価が発生する初めての機能)ため、価格設計を慎重に行う必要がある。
**規模: M** / 依存: **API利用料(継続コスト)、APIキー管理の方針決定(人間の判断)が必要**

### 9. 天候連動コメント
「今日は暑いから水分補給を」のような、外部の天気APIと連動した気遣いコメント。効果は面白いが、外部APIの利用規約・APIキー・ネットワーク依存(オフライン再生の強みが薄れる)を天秤にかける必要がある。
**規模: M** / 依存: **外部天気APIのAPIキー取得(人間の作業)が必要**

## 優先度D: 大掛かりだが検討の価値があるもの

### 10. Apple Watch対応 / ロック画面ウィジェット・Live Activities
腕時計だけで操作・確認できるようにする、あるいはロック画面に距離・ペースをリアルタイム表示する。実装規模が大きく、Watch用の別ターゲットやLive Activities用のWidget Extensionが必要になるため、v1の反応を見てから着手するのが妥当。
**規模: L** / 依存: **Xcodeでのネイティブターゲット追加が必要(EAS Buildだけでは完結しない可能性が高い)**

### 11. 多言語UI(英語)
現状は日本語UI+説明文だけ英語対応。UI文言自体をi18n化すれば、Product Hunt/Reddit経由の海外ユーザーもアプリ内で迷わなくなる。`personas.ts` の台詞バンクも英語版が必要になるため、翻訳コストが実装コストを上回る。
**規模: M(UI)+ L(台詞翻訳)** / 依存: なし

### 12. ソーシャル機能(友人との記録比較・ランキング)
記録を友人と共有したり、ランキング化する。エンゲージメントは上がるが、バックエンド(ユーザー管理・データ同期)が必要になり、「オフライン完結・データ収集なし」という現在の設計方針からの大きな転換になる。時期尚早、v2以降の検討事項。
**規模: XL** / 依存: バックエンド新規構築、プライバシーポリシーの全面見直し
