# リリース手順書(人間がやる作業)

実装・ブランド素材・ストア文言はここまでの作業で用意済み。ここから先はApple/Googleの開発者アカウントを持つ人間でないと進められない作業をフェーズ別にまとめた。凪の `release-runbook.md` と共通する部分が多いため、両アプリを同時にリリースする場合はPhase 1・2の開発者アカウント登録は共用できる。

## 概要

| 項目 | 目安 |
|---|---|
| 初期費用 | 約¥19,000(Apple $99/年 + Google $25一度きり、凪と共用可) |
| 登録〜審査提出までの期間 | 3〜10日 |
| Macの要否 | **不要** — EAS Buildでクラウドビルド可能 |

## Phase 1〜2. 開発者アカウント登録・EAS Buildの準備

凪の `docs/release-runbook.md` のPhase 1・2と同一。既に凪で登録済みなら、このアプリではPhase 3から着手できる。ただし本アプリはネイティブの位置情報モジュール(`expo-location`)を含むため、Expo Goでは一部機能(GPS計測)が正しく動作しない場合がある。**開発ビルド(`eas build --profile development`)またはdevelopment client経由で確認することを推奨。**

## Phase 3. アプリ内課金商品の作成

💰 無料(手数料はストア側の標準率) / ⏱ 1〜2時間+実装差し替え

- [ ] App Store Connect で非消耗型商品を作成。Product ID例: `unlock_all_tones`。価格は¥480に近いTierを選択
- [ ] Google Play Console で管理対象アプリ内アイテムを作成(同じProduct IDで揃える)
- [ ] `react-native-iap` を導入し、`app/purchases.ts` を差し替え(手順はファイル冒頭のコメントに記載、凪と同じパターン)
  ```bash
  npm install react-native-iap
  ```

## Phase 4. 位置情報まわりの確認

💰 ¥0 / ⏱ 半日〜1日

凪には無かった、本アプリ固有の確認事項。

- [ ] 実機でGPS計測の精度を確認(市街地・公園・屋内での挙動差)
- [ ] バッテリー消費を確認。長時間のランで著しく消費が早い場合は `watchPositionAsync` の `timeInterval` / `distanceInterval` を調整(`app/useRunSession.ts` 内)
- [ ] iOS/Androidそれぞれで位置情報の許可ダイアログの文言(`app.json` の `locationWhenInUsePermission`)が意図通り表示されるか確認
- [ ] Android実機でTTS発話時に音楽アプリ(Spotify等)がどう振る舞うか確認。ducking(音量が下がるだけ)にならず完全に止まってしまう場合は、機種依存のTTSエンジン挙動の可能性が高く、README記載の既知の制約に該当する

## Phase 5. 音声品質の向上(任意)

💰 ¥0(端末標準TTSのまま)〜 数千円/月(高品質TTS API) / ⏱ 任意

凪の「音源の実録音への差し替え」に相当するフェーズ。本アプリは著作権の問題は無いが、端末標準TTSは声優収録ほど自然ではない。

- [ ] そのまま(¥0)でリリースし、反応を見てから判断するのがおすすめ
- [ ] 音質を上げたい場合、ElevenLabs等の高品質TTS APIへの切り替えを検討(API利用料が発生し、オフライン再生ができなくなる点に注意)
- [ ] 予算が確保できれば声優収録も選択肢だが、MAPLUS+と同じコスト構造になり本アプリの価格優位性が薄れる点に留意

## Phase 6. 法務ページの仕上げ

💰 ¥0 / ⏱ 15分

- [ ] `docs/legal/privacy-support.html` のお問い合わせ先を実際のメールアドレスに差し替え
- [ ] ページを公開してURLを取得(アーティファクトの共有設定を「公開」に、または自前ドメインでホスティング)
