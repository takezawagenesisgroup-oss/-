# 採用エントリー自動化プロトタイプ

求人広告経由の応募から面談日程調整までを、HR B社のLINEグループ運用に代わって
自社で完結させるための設計書 兼 動くプロトタイプです。

## 1. 背景・目的

現状のフロー:

```
求人媒体で応募 → HR B社がグループLINEを作成
                → 求職者・HR B社・自社でグループLINE上で日程調整
                → 面談当日、紙の面談シートを記入 → 面談開始
```

課題:
- 日程調整のたびにHR B社を介する必要があり、費用が発生している
- 面談当日に面談シートを記入するため、面談開始が遅れる
- 求職者の情報を事前に把握できない

今回実現したいフロー:

```
求人媒体で応募 → 自社Webフォームで基礎情報入力 → その場で面談日程を選択
              → （任意）公式LINEと連携し通知を受け取る
              → 面談シートを事前にWebで入力（紙の記入をなくす）
              → 面談当日はすぐに面談を開始
```

これにより、(1) 即時に面談を実施できる、(2) 事前に候補者情報を得られる、
(3) HR B社への支払いが不要になる、の3点を実現する。

```

│ フォーム）    │                  └─────────┬──────────┘
└─────────────┘                            │ 空き枠から選択
                                            ▼
                                  ┌──────────────────┐

                                  └─────────┬──────────┘
                                            │
                     ┌──────────────────────┼───────────────────────┐
                     ▼                                              ▼
          ┌────────────────────┐                        ┌────────────────────────┐
          │ 公式LINE友だち追加  │                        │ 面談シート事前入力       │
          │ → 連携コード送信   │                        │ /interview-sheet/[id]  │
          │ → 通知を受信       │                        └────────────────────────┘
          └────────────────────┘
                     │
                     ▼

管理側:
┌────────────────────┐   ┌──────────────────────────┐
```

技術スタック: Next.js (App Router) + TypeScript + Prisma(SQLite) + LINE Messaging API + Tailwind CSS

## 3. データモデル（`prisma/schema.prisma`）

| モデル | 役割 |
|---|---|
| `Applicant` | 応募者の基礎情報、ステータス、LINE連携コード/ユーザーID |
| `AvailabilitySlot` | 管理者が事前登録する面談可能枠（日時・定員） |
| `Appointment` | 応募者と枠の予約（1応募者につき1件） |
| `InterviewSheet` | 面談シートの回答。**項目未確定のためJSON文字列で保持** |
| `Notification` | LINE通知の送信ログ（成否・本文） |

`Applicant.status` は `BASIC_INFO_SUBMITTED → SLOT_SELECTED → SHEET_SUBMITTED →
INTERVIEW_DONE` と遷移する。

## 4. LINE連携方式

今回は「独立したWebフォーム＋LINE通知」方式を採用（LIFFは使わない）。

1. 応募者はWebフォームで基礎情報を入力し、そのままブラウザ上で日程を確定する
2. 待機画面に固有の「連携コード」が表示される
3. 応募者が公式LINEアカウントを友だち追加し、そのコードをトークに送信する
4. Webhook（`/api/line/webhook`）がコードを応募者に紐付け、以後 `lineUserId` 宛に
   プッシュ通知を送れるようになる
5. 日程確定・面談シート未提出リマインドなどを `notifyApplicant()`（`lib/notify.ts`）
   経由で送信する

LINEチャネル未設定（`LINE_CHANNEL_ACCESS_TOKEN` 未設定）の場合は自動的に
**モックモード**で動作し、送信内容をコンソールに出力するだけになる。
そのため、実際のLINE公式アカウントを用意していない開発中でも全フローを検証できる。

## 5. 日程調整方式

今回は「手動登録した空き枠から選択」方式（外部カレンダー連携なし）。

- 管理者が `/admin/slots` で面談可能な日時・定員を登録
- 応募者は基礎情報入力後、空いている枠から即座に選択（先着順、定員に達した枠は非表示）
- 二重予約はトランザクションで防止

## 6. 面談シートについて（現時点では仮項目）

実際の紙の面談シートの項目リストはまだ受領していないため、`lib/interviewSheetFields.ts`
に一般的な採用面談項目（最終学歴・職歴・志望動機など）を仮で定義している。

**実物の項目リストを受け取り次第、この配列を差し替えるだけでフォーム・保存先ともに
反映される設計にしている**（回答はJSONで保存するためスキーマ変更は不要）。

## 7. 画面一覧

| パス | 内容 |
|---|---|
| `/` | 求人媒体からの遷移先を想定した入口ページ |
| `/apply` | 基礎情報入力フォーム |
| `/apply/[id]/schedule` | 面談日程の選択 |
| `/apply/[id]/waiting` | 日程確定後の待機画面（LINE連携・面談シート導線） |
| `/interview-sheet/[id]` | 面談シート事前入力フォーム |
| `/admin/slots` | 面談枠の管理者登録・削除 |
| `/admin/applicants` | 応募者一覧・詳細（面談シート回答・通知履歴を確認可能） |

## 8. セットアップ

```bash
npm install
npx prisma migrate deploy   # 初回のみ。SQLiteファイル(dev.db)を作成
npm run dev
```

`http://localhost:3000` にアクセス。管理画面は `/admin/applicants`。

### 環境変数（`.env`）

`.env.example` を参照。LINE連携を有効にする場合は以下を設定する。

```
LINE_CHANNEL_ACCESS_TOKEN=  # LINE Developersのチャネルアクセストークン
LINE_CHANNEL_SECRET=        # 同チャネルシークレット（Webhook署名検証に使用）
LINE_OFFICIAL_ACCOUNT_URL=  # 友だち追加URL（例: https://line.me/R/ti/p/@xxxxxxx）
```

未設定の場合はモックモードで動作する。
